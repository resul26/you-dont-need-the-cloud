Chapter 22

Failure Modes and Fixes

Local LLM failures are rarely mysterious. They're almost always one of: memory fit, formatting, runtime support, decoding settings, or retrieval quality. Bookmark this chapter.

SymptomLikely causeFix
Out of memoryWeights + KV + overhead > availableSmaller model, less context, lower concurrency, better quant, more headroom
Gibberish or role confusionWrong chat template, wrong tokenizer, wrong BOS/EOSCheck model card, verify runtime template before blaming the model
Slow first tokenPrefill is expensiveShorter prompt, prefix caching, better retrieval, less context, faster runtime
Slow streamingDecode bottleneckMore bandwidth, different quant, no CPU spill, attention backend, speculative decoding, model is too big
Bad document answersRetrieval failureInspect parsed text, chunk boundaries, metadata, top-k, reranking
Bad JSON / tool callsDecoding or schemaLower temp, constrained decoding, stricter schemas, better examples, tool-tuned model
Repeating loopsDecoding or templateReduce temp / top-p, add repetition penalties, check stop tokens, verify template

Boring checks first. They fix more problems than flag-day model swaps.
