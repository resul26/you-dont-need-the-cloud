Chapter 6

The VRAM Tax Nobody Mentions Until It's Too Late

Here's the part that breaks people. They do the Chapter 5 math, they confirm that the 13B model "fits" in 8 GB of VRAM, they load it, and it crashes on the second prompt. Why? Because weights are only part of the bill.

Your total memory consumption, in roughly the order you'll discover it:

  • Model weights — the formula from Chapter 5. Easy. Predictable.
  • KV cache — Chapter 3. Grows with context length. Quadratically in your soul, linearly in RAM. This is the silent killer.
  • Activations — runtime-managed, but vary a lot by optimization level. Some runtimes hog more than others.
  • Batch / concurrency memory — every concurrent request gets its own cache slice.
  • Framework overhead — Transformers, vLLM, TensorRT-LLM, llama.cpp all take different cuts. CUDA graphs reserve extra memory for latency stability.
  • Speculative decoding memory — draft models, draft heads, verification buffers. They're not free.
  • LoRA adapters — small, but nonzero.
  • Vision encoders — your "single image" is a few thousand extra context tokens plus some extra memory. Count it.

A realistic estimate looks like:

total memory ≈ quantized weights + KV cache at your context + runtime overhead + concurrency overhead + safety margin

And the classic failure mode: a 13B model in Q4 fits at 8K context, and then dies at 32K because the KV cache quadrupled and there was no headroom. The weights didn't change. The context did.

Rule of thumb, and genuinely just memorize it:

Add 10–30% extra VRAM for a comfortable run. Add more if you're doing long context, high concurrency, or agent workloads.

Estimates only. Weights = params × GB-per-billion for the quant. KV cache assumes a GQA-class model scaled with size (the appendix has the exact per-model math). Overhead = 20% for runtime + activations + headroom. Your mileage will vary by engine — measure, don’t trust, this included.

And don't run at 99% VRAM utilization. Spinning all the way to the ceiling is begging for OOMs and fragmentation. 80–90% is the ceiling you pretend is the ceiling. That's the "memory gate":

weights + KV + overhead ≤ 80–90% of available memory
