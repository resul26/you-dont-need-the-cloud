Chapter 18

Chat Templates (Or: Why Your Model Sounds Drunk)

Here's the most common silent bug in local LLM evaluation. A chat model was trained with specific markup. Maybe something like:

<|system|> You are a helpful assistant. <|user|> Explain KV cache. <|assistant|>

Maybe a ChatML-style variant. Maybe it wants [BOS] [INST] ... [/INST]. Maybe it needs reasoning tokens. Maybe it wants tool calls in a particular XML or JSON envelope.

Use the wrong template and you don't get "slightly off answers," you get: gibberish, role confusion, the model echoing your prompt, refusal weirdness, broken tool calls, bad benchmarks, and the good old classic conclusion — "this model is dumb" when the template was the actual bug.

Best practices:

  • Use apply_chat_template from the tokenizer when you're in Transformers-land.
  • Use model-specific templates in Harbor-backed frontends, llama.cpp, LM Studio, vLLM, or SGLang.
  • Check whether your model is base, instruct, chat, reasoning, or tool-tuned. Different templates.
  • Sanity-check BOS/EOS. One token off can ruin your afternoon.
  • Keep system prompts short unless they really need to be long.
  • For tool use, follow the exact schema the model expects.

The cardinal sin: building an app that lets users swap models but hardcoding one template. That is the #1 local-model eval bug. Treat the template as an API contract. Don't be the reason your own model looks bad.
