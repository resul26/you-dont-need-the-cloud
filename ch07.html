Chapter 7

MoE, GGUF, and Other Things That Aren't Magic

The MoE trap. Mixture-of-Experts sounds bigger than it runs. "8x7B" reads like 56B. It's not.

  • Only a subset of experts runs on any given token. Compute per token is small.
  • Compute cost ≠ memory cost. Total parameters affect whether it fits; active parameters affect how fast it runs.

Depending on loading: you might need memory for all the experts anyway (common on local setups), or you can shard experts across GPUs (more advanced). Treating MoE like a dense model leads you to either wildly overestimate or wildly underestimate. Neither is fun. Both are common.

GGUF is not magic. GGUF is great. It's also, specifically, the llama.cpp ecosystem's binary format. Those magical Q4_K_M numbers you saw? They're true inside llama.cpp.

The moment you load the same model into a different runtime, it might:

  • Dequantize parts of the model back to higher precision
  • Hold extra copies for operational reasons
  • Use a different memory layout

"It fits in 6 GB" is runtime-specific truth. Ask "in what engine" before you trust any such claim.

safetensors vs. .bin. One is a safe file format that just holds tensors. The other is Python pickle — which can, in principle, execute arbitrary code when loaded. Local AI security rule #1:

Do not let a stranger's model file become a stranger's code execution.

Use safetensors whenever possible. Avoid random .bin files from untrusted sources. Do not enable trust_remote_code if you don't understand why it needs to run remote code. These are the boring rules that save you from the exciting problems.

One-line summary of formats:

  • safetensors — safe, default for PyTorch/Transformers folks.
  • GGUF — llama.cpp's quantized format. LM Studio uses it. It's everywhere in the desktop world.
  • ONNX — standardized deployment, useful especially outside the typical PyTorch stack (Intel NPUs, ARM, custom silicon).
  • EXL2 / EXL3 — ExLlama's local CUDA quant formats.
  • GPTQ / AWQ — the older GPU quant formats, still common.
  • TensorRT format — meant for TensorRT-LLM on NVIDIA data-center paths.

The format decision isn't cosmetic. It decides what engines can run your model, in what quant, and at what speed. Pick the engine first (we'll get there), then find the model in the right format for that engine.
