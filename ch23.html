Chapter 23

How to Grow Your Stack

Alright, the growth path. Nobody needs to start at TensorRT-LLM. Start where your problem actually is.

Beginner — Easiest Useful Setup

  • Stack: Harbor or LM Studio
  • Model: recent 4B–9B instruct, Q4 quant, 8K–32K context
  • Goal: learn prompting, compare models, understand speed and memory, avoid custom code.

Intermediate — Developer Setup

  • Stack: llama.cpp or Transformers, GGUF or safetensors, OpenAI-compatible local server, simple RAG, small eval set
  • Goal: build local apps, test retrieval, measure quality, serve from localhost to real scripts.

Advanced — Private Serving Setup

  • Stack: vLLM or SGLang, 1+ GPUs, OpenAI-compatible API, monitoring, prompt/version management, eval suite, RAG with reranking, tool sandboxing
  • Goal: serve real users / internal workflows, tune throughput and latency, maintain safety and observability.

Expert — Custom Optimization

  • Stack: TensorRT-LLM, custom kernels, quantization experiments, speculative decoding, multi-GPU parallelism, fine-tuning, distillation
  • Goal: trade engineering time for efficiency at scale.

And the model-choice pre-flight checklist, which you should run before falling in love with any checkpoint:

  • Task fit — chat, coding, documents, agents, multimodal, edge, fine-tuning?
  • Memory fit — weights + KV + overhead + margin ≤ 80–90% of available?
  • Interface fit — tokenizer, template, stop tokens, tool schema, reasoning mode?
  • Runtime fit — does your engine actually support this architecture + quant + context + serving mode?
  • License fit — can you legally use this for the thing you're building?

When you're comparing candidates, run the same 20–50 prompts through each. Real tasks. Coding edits. Document Q&A. JSON output. Summaries. Tool calls. Long context. Measure quality, latency, memory, template reliability, failure modes. Your workload is the benchmark.
