Appendix C

Glossary

  • Activation — intermediate computations the model holds during forward passes.
  • Attention — the mechanism that lets each token look at earlier tokens. MHA, MQA, GQA are common variants.
  • Bos/EOS — "beginning of sequence" / "end of sequence" tokens. Special control markers.
  • Chat template — the exact markup format the model expects when having a conversation. Critical to get right.
  • Continuous batching — serving technique where new requests are merged into an in-flight batch every iteration.
  • Decode — the sequential phase where answer tokens are generated one at a time. Bandwidth-bound.
  • GGUF — llama.cpp's binary model format. A container plus quant strategy.
  • GQA / MQA / MHA — grouped-, multi-query, and multi-head attention. Affect KV cache size, speed, and quality.
  • Inference — running the model. In LLM-land, synonymous with "generation."
  • KV cache — the model's working memory of prior tokens. Explains long-context memory pain.
  • LLM — large language model, bless.
  • LoRA — low-rank adapter, a small fine-tuning add-on that doesn't need a full copy of weights.
  • Logits — raw model scores before softmax.
  • MoE — mixture of experts. Only some experts run per token. Compute cost ≠ memory cost.
  • Prefill — the parallel-ish phase of processing your prompt. Compute-bound.
  • Prompt injection — hostile instructions embedded in retrieved content.
  • Quantization — storing weights in lower precision to save memory / sometimes gain speed.
  • RAG — retrieval-augmented generation. Get the docs, don't stuff the prompt.
  • RoPE — rotary position embeddings. How modern models track token order.
  • safetensors — safe tensor serialization format. Prefer it over .bin files.
  • Speculative decoding — drafting candidate tokens cheaply and verifying them in parallel. Speeds up decode.
  • Tensor parallelism — splitting tensors across GPUs. Needs strong interconnect.
  • TTFT — time to first token. Prefill latency.
  • TPOT — time per output token. Decode speed.
  • Transformer — the architecture almost every modern LLM uses.
  • Unified memory — Apple Silicon / DGX Spark style memory pool shared by CPU and GPU. Good capacity, moderate bandwidth.
  • vLLM — popular production engine. PagedAttention, continuous batching, broad quant support.
  • VRAM — GPU memory. Capacity.
  • Bandwidth — how fast that memory can move. Speed.
